# Official ComfyUI template mapping survey (#948)

Audit pin: [Comfy-Org/workflow_templates@3c2199b9362457b12b9c60c6cc303501526ebd62](https://github.com/Comfy-Org/workflow_templates/tree/3c2199b9362457b12b9c60c6cc303501526ebd62/templates).
The MIT-licensed index contains **727 workflows**; all 727 JSON files were inspected, including
277 files with embedded subgraphs. The other 16 JSON files are indexes, schemas or metadata,
and are not workflows. Upstream `usage` at this pin determines the order below; it is not a live
popularity ranking. Original Git blob ids and sizes were verified before inspection.

**Work in progress:** seven candidate profiles are stored in
[`template-mappings.v1.json`](../assets/comfy/template-mappings.v1.json). Four have import tests;
three video profiles still need their missing server schemas verified. The two other most-used
subgraph families use dynamic widgets that the importer currently refuses. This survey does not
claim that every template runs, or that structural matching alone verifies a server contract.

The field column records user-facing subgraph interfaces and recognizable unconnected scalar
widgets from available node descriptors. Media comes from loaders and the upstream index IO
hints, with reference filenames omitted. A `node:media` entry is an upload candidate. `instance.field`
names a promoted field, while ordinary `node.field` names a widget. A `node.widget[index]`
selector keeps the server label and requires the exact pinned widget count and kind on a node
with no input sockets; this avoids inventing unknown server parameter names. Model filenames, file prefixes,
helper expressions, system prompts and other internal widgets are excluded. Result candidates
are savers (plus media previews that may need conversion to a compatible saver). A result's node
id remains significant even when several savers share one media list port.

**Mapping status:** curated import tests exercise conversion and discovery against pinned,
redacted fixtures with recorded descriptor facts plus explicitly synthetic missing core classes.
The four tested image/audio/API fixtures also pass client workflow validation and bounded request
serialization; they have not been submitted to a live server. Connection-only V3 Autogrow and
MatchType are covered offline, while DynamicCombo serialization remains unsupported.
Candidate means the profile is not yet verified for import. Surveyed means this is an inventory,
using generic discovery when the server can describe it; unknown descriptors and dynamic widgets
need further validation. The absence of a recognized field/result is a recorded gap, not proof that
one does not exist. No paid jobs were submitted. Tests make no network calls.

**Merge blocker:** the user requires validation against a live ComfyUI instance after offline
work is complete. Recorded descriptors, synthetic catalogs, import tests and mock submission
checks cannot clear this blocker. Keep the PR draft and do not merge it until live validation
of the mapped contracts, fields, media inputs and request acceptance is recorded.

Matching ignores prompt/model values, titles and layout. It retains node classes/ids, execution
modes, port order, links, saved-widget counts and proxy bindings. Changed graphs or server types
fall back to generic discovery. Explicit `params` overrides curation, and the field editor's saved
mapping remains authoritative. Inputs that upload media and partner-credit evidence are retained.
