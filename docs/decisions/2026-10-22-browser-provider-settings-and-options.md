## 2026-10-22 · Browser provider settings and asynchronous option lists (#721)

The browser's Providers panel edits ComfyUI and LiteLLM server roots through
`providers.settings_get` and `providers.settings_set`. The engine stores the two addresses and
ComfyUI installation salt as one bounded JSON record in the origin's localStorage. Provider
keys remain in their separate OriginStore entries. HTTP(S) addresses are bounded and normalized;
credentials, queries and fragments refuse without echoing their contents. An explicit successful
Save publishes both the durable and live configuration. Read failures/corruption report a
value-free notice and leave an editable default; no stored record is overwritten until Save.
Automation may read the addresses, but changing the destination of provider requests and their
credentials remains human-only, like editing API keys.

Settings hold a list of ComfyUI servers since #864; the browser keeps one. `comfyui_url` is saved
as the only, default server of that list, named by its host and port, and a record saved before
the list still loads its `comfyui_url`. Several servers in the browser are left for later.

The salt is generated by the engine's fallible entropy source on the first successful Save and
survives reloads. LiteLLM uses its configured root plus `/v1` and the optional `litellm` virtual
key account. The panel explains direct browser calls, server CORS configuration and the browser's
HTTPS-to-HTTP restriction. The shipped catalog has no LiteLLM models, so this saves configuration
ahead of catalog support; no card can select or call the proxy yet. No proxy or shared credential
service is added.
The catalog follow-up belongs to [#489](https://github.com/CypherNaught-0x/nodecraft/issues/489),
which requires a recorded integration decision before implementation.

The existing option-fetch service gains a page-future backend alongside its desktop worker.
`options.refresh` still answers with a pending ID at once and refuses a second concurrent fetch.
The page creates an owned future on the next tick, polls it without blocking, and installs the
answer on a later frame through the engine's existing `finish` path. Its waker requests repaint;
no browser path calls `block_on`, starts a thread or uses a native clock.

Saving new endpoints invalidates cached provider routing and pending confirmations before the
next input frame. It drops pending asynchronous option work and clears the installed list cache,
so a late reply from the old server cannot become the new server's options. Cancelled pending IDs
receive a terminal error report; an idle endpoint change clears the previous installed-list report.
Runs already handed
to a provider keep their existing adapter. Native fake-origin tests cover persistence, refusal,
repair and secret exclusion; kittests exercise a genuinely pending future, later-frame picker
installation and endpoint-change cancellation. Wasm compilation is separate from live browser
networking evidence.
