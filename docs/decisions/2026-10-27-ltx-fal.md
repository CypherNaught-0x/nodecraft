## 2026-10-27 · LTX video through the existing fal queue (#30)

Reuse fal's credential, saved async tasks, origin restrictions, bounded downloads and ambiguous
submission policy for LTX 2.3 Pro text-to-video and frame-to-video. New requests have a separate
strict schema module; no SDK, feature, credential or native API client is needed. The native
LTX v1 API retired on 2026-10-26, and is not an implementation target. See the dated
[provider contract and primary sources](../providers.md#ltx-video-through-fal).

Expose only API schema enum values, rather than broader marketing claims about duration.
Frame mode uses explicit landscape or portrait aspect ratios. Catalog FPS choices are text;
request serialization converts the accepted choice to the required integer. Frame inputs retain
fal's existing bounded decode. LTX gets the video result quota of 256 MiB, including the aggregate
bound, so a supported high-resolution clip is not constrained by the image output cap.

fal's price page conflicts internally. Keep quotes unknown and require explicit unpriced-job
acceptance until an authoritative rate is available. A remote billable-unit header is evidence
of units, not a USD invoice. A lost submit reply remains terminal under fal's existing policy;
accepted handles resume without creating another paid job.
