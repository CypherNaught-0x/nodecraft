## 2026-10-18 · Finite mock lifecycle scripts (Part of #275)

- `MockProvider::scripted` adds explicit bounded model/operation/key configuration. `MockModel` remains Copy; legacy constructors and permanent `MockFailure` behavior remain unchanged. The single implementation stays in providers::mock and existing facade/legacy reexports share it.
- Four distinct finite stages model preaccept refusal, accepted lost replies, per-handle poll transport errors and provider-reported failed generations. A failed generation needs its next explicitly declared sent key; only exposed terminal failure unlocks that key. Cancellation or success closes replacements. Providers does not derive engine keys.
- Accepted key identity precedes every changed retry payload. Lost replies bill once; poll errors do not consume progress. Terminal failure/cancellation overrides leftover lost replies. Successful results retain those slots. All runtime transitions share the existing mutex and occur at method construction, before the returned ready future is polled.
- Zero stages normalize to absent. Constructor limits are64 models,64 operations,64 keys per operation/4096 total; names/keys64 ASCII bytes, stage counts1024, failed-generations additionally <=keys-1 (at most63). Lengths are checked before copies. Bounds cover retained/copied configuration, not caller allocations or legacy request logs. Errors are static.
- Clone shares counters and accepted state; reconstructing a provider resets only the new instance. No reset/fresh API is added. Handle strings may alias between independent instances: cross-instance use is unsupported, not detected or rejected. No globally unique authority is claimed.
- Conservative legacy submit delivery evidence is preserved. This supplies requirement5 fixtures, not real Driver goldens, budget policy changes, catalog/instance admission or durable state. Those remain separate #275/#254 work.
