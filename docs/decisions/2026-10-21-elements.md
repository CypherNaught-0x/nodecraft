## 2026-10-21 · Elements are live nodes, and a #mention is a wire the planner adds (#104)

- **An Element is an action node.** It holds a name, a category and guidelines as parameters,
  takes up to eight ordered images on `images` and passes them through on `reference`. It costs
  nothing to run and is recomputed live like other actions, so editing or re-ordering its images
  makes everything that uses it stale. It is live within a project: there are no pinned
  versions. A library copy (shared across projects, #552) is placed as a copy, so editing it
  later never changes a placed one.
- **The reference sheet is a generation card.** `element.sheet` wires the images into an
  ordinary image card with a sheet prompt built from the category and guidelines, and that card's
  output into the Element's `sheet` input. The card's history is the Element's reference history
  and its active result is the default reference, so regenerating, picking another result and
  showing the price first all come from the card. While the card has no result the Element gives
  its images instead, and planning the Element doesn't run the card. The card is wired from the
  images the Element has when it is made; images added later are wired into the card by hand
  (or the sheet is removed and made again). Guidelines lose any `#` on the way into the sheet
  prompt, so the sheet never mentions an Element.
- **A mention is an implicit wire.** `#name` in a prompt (letters, digits, `-`, `_`, compared
  ignoring case) feeds that Element's `reference` into a generation card's first image list input
  that takes more than one image (never a single init image), after any wired images. Only a
  typed prompt mentions: a wired prompt replaces the text, so it feeds nothing. Routing adds the feed, so the planner, staleness and cost see it exactly as
  they see a wire, and a loop made through a mention is reported as a loop. A tag no Element goes
  by (`#ff0000`) stays text. An Element already wired into the card, directly or through routers, isn't fed twice.
  Renaming or deleting an Element turns its mentions back into text; the cards that used it go
  stale, and the card hint stops listing the name, but nothing warns louder than that. A name two
  Elements share blocks the mentioning card until one is renamed; `element.create` refuses to
  make such a pair, but an old or hand-edited file can hold one.
- **An Element is not an identity.** Mentioning or wiring an Element sends its pictures as
  reference images. Training a provider identity, preset or LoRA from them is a separate,
  explicitly priced step (#180).
