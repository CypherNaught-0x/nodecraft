## 2026-10-22 · Decks are cards whose slides are layer stacks (#122)

- **A deck is a document, held by a Deck card.** `structure.deck` is a structure card with no
  ports that never runs, like a Note. Its slides live in the card's
  `config["nodecraft.deck"]` as JSON (`{"version": 1, "slides": [...]}`), so they save, undo,
  sync and copy with the card. Presenting nodes or fields means making a deck from them
  (`deck.create`, one slide per node and one per field). The deck is then edited and presented
  like any other deck. Presenting is a view of the deck, never a separate kind of data.
- **A slide is a Layer Editor layer stack.** Slides reuse the `nodecraft-actions::layers` model:
  text, shape and source layers, each with the same box, transform and style fields and the same
  checks. The deck's frame (width, height, background) is a set of card parameters named as on the
  Layer Editor, so the two draw the same way.
- **Sources stay live.** A source layer names a canvas node by id and the `nth` image it shows.
  It draws whatever that node shows now: its image, or its text for a text-producing node. When
  the node is deleted or has no output yet, the layer is kept and marked missing, and the slide
  draws an empty box in its place. A deck never copies media, so it adds nothing to the project's
  size, and a re-run shows up on the slide.
- **Readable data is never dropped.** Fields a newer NodeCraft adds to a deck or a slide are kept
  when this one edits it. A stored layer this version can't read (an unknown kind, or values out
  of range) is listed as unsupported, isn't drawn, and is kept where it is. A deck whose `version`
  is newer than this build understands is listed read-only and every edit to it is refused.
- **Edits are commands with revision checks.** `deck.list` returns the document revision with
  every slide. Each `deck.*` edit takes an optional `expected_revision` and is refused with a
  conflict when the document has moved on. This is the same rule discussions use, so an agent
  (#114, #116) never overwrites a change it hasn't seen. Each edit is one `SetNode` changeset, so
  one undo step.
- **Limits:** 256 slides, 64 layers a slide (the Layer Editor's limit), and 1 MiB of stored deck.
  Ids are the layer id alphabet.
- **Presenting is a full-window view.** It answers the arrow keys, Space, Page Up, Page Down,
  Home, End and Escape. It draws each slide with the Layer Editor's on-screen drawing, so a slide
  looks the same in both.
- **Known limit: copies keep their sources.** A pasted or duplicated deck still points at the
  original nodes, even when those nodes were copied with it, because copying doesn't remap the
  deck's source ids yet. Each source still draws the node it names, or an empty box once that
  node is gone.
- **Slides are edited on the Layer Editor's stage (#694).** A Deck card's "Edit slides…" opens a
  full-window editor: the slides as thumbnails to pick, drag into order, add, remove and name,
  and the picked slide on the Layer Editor's stage, layer list and fields. The Layer Editor code
  takes the slide as its target, so both editors share one set of gestures and fields.
  Every change is a `deck.*` command. A drag, a nudge, an alignment, a reorder or a removal
  rewrites the slide's layers in one `deck.slide_update`, so it is one undo step. Each command
  carries the revision the editor last listed, and a command after it in the same frame carries
  the revision its predecessor left. Layers the editor can't read are passed back untouched, in
  place. Text on slides draws in Lato, so the slide editor offers no font picker.
- **Not decided here:** exporting rendered slides or a PDF, and custom fonts in decks. Each has
  its own issue.
