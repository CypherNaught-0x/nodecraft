## 2026-10-22 · Live sharing: a yrs mirror, changesets in, a relay in the CLI (#119)

People working on one project at once share it through a **CRDT mirror** of the document, not
by sending changesets to each other. Each peer keeps its `Session` as the only thing that edits
its project; a `Collab` (`crates/engine/src/collab.rs`) sits beside it and moves edits between
the session and the shared document.

**The CRDT is [yrs](https://github.com/y-crdt/y-crdt) 0.28 (MIT)**, the Rust port of Yjs. It is
a dependency, not vendored code. Its update format is stable, it builds for wasm, and its maps
give the merge we want without our own CRDT. Anything else that reads the shared document has to
speak the same yrs update format.

**Each part of the project is one map entry**, a JSON string under a key naming it. The new
`nodecraft-sync` crate (L2) owns this as `Mirror`. Its root maps are `meta`, `canvases`, `nodes`,
`positions`, `params`, `edges`, `fields`, `tags`, `comments` and `skills`. Keys are
`<canvas>/<id>`, and parameters are `<canvas>/<node>/<name>`. A card is split three ways:
its position, each parameter, and the rest. That way one person can drag a card while another
edits its prompt, and both changes stay. When two people change the same entry, every peer ends
with the same one of the two (yrs's last-writer rule). A technique canvas is frozen, so it is
one entry, whole.

**Changes go out as diffs and come back as changesets.**

- `publish` compares the session's document with the last one it shared (the "shadow") and writes
  only the entries that changed.
- `materialize` reads the shared document into a `Project` through `graph::assemble`. This puts
  back together whatever the merge produced: wires to removed cards, two wires into one input,
  cycles, entries that can't be read, and parts over the caps are dropped. The peer then writes
  those repairs back, so every peer drops the same things.
- `graph::diff` turns the difference into changesets, in chunks of at most 8 MiB, so each fits the
  16 MiB history budget. `Session::apply_remote` applies them through the one mutation path.

**Remote edits join no undo step.** Undo and redo stay each person's own. An undo after a remote
edit puts back what this person had for the parts it touches. If someone else removed a part
that the undo needs, the undo fails with an error instead of a panic, and the history is kept.
Remote edits go into the event log as `sync.remote`.

**Assets travel separately.** Cards name assets by hash. Before applying an update, a peer asks
for every asset that update needs and doesn't have yet (`AssetGet`). It applies the update only
once they have all arrived. The room keeps the assets it has passed on (512 MiB per room), so a
late joiner gets them even after the sharer has left. Assets over 16 MiB aren't shared yet.

**The protocol** is binary WebSocket frames: one tag byte and a body (`nodecraft_sync::Frame`).

- The frames are `Hello` (protocol version and room id), the yrs sync steps `Step1`/`Step2`,
  `Update`, `AssetPut`/`AssetGet`, and `Refused`.
- `PROTOCOL` is 1. A relay refuses a peer that speaks another version.
- A frame is at most 64 MiB. An `AssetPut` is checked against its hash on decode.

**Rooms are capabilities.** A room id is 32 random bytes in hex, and anyone who has it can join.
It never appears in a log or an error, and `RoomId`'s `Debug` output is redacted.

**The relay lives in `nodecraft-cli relay`**, not in a library: library crates must build for
wasm, and the relay needs sockets and threads. It runs one std thread per connection on
`tungstenite` (blocking, with the `handshake` feature only). The room logic
(`nodecraft_sync::Room`) is socket-free, so it is tested in memory and a different host could use
it. The relay keeps nothing on disk and drops a room when its last peer leaves. It caps
connections (256), rooms (64), peers per room (32), bytes merged per room (512 MiB), and frames
waiting for one peer (32). A peer that falls further behind than that is dropped. The relay
speaks plain `ws://`, so put it behind a TLS proxy before anyone reaches it over a network.

**Not done here** (follow-up issues): the desktop Share and Join UI, a browser transport,
presence (#121), and sharing assets over 16 MiB.
